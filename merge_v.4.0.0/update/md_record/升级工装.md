# 升级工装逻辑说明

> 工程: `update/projects/ev_hc32f460_lqfp100_v2/UDS`
> 核心文件: `upgrade_tool.c` (状态机) / `tool_config.h` (参数) / `isotp_transport.c` (ISO-TP) / `canif.c` (CAN 抽象)

## 1. 角色定位

升级工装作为 **UDS Tester (客户端)**，模拟 TBOX 角色：

1. 监听产品心跳 (0x18FF1108)，解析 8 位十进制版本号 MMMM.mmmm (byte[0..3]=主版本4位, byte[4..7]=次版本4位)，折算为主*10000+次后数值比较
2. 比对版本：产品版本 < 工装版本 → 自动发起全量固件刷写 (96KB)
3. 升级流程全部为工装主动请求、产品应答的 UDS 诊断服务
4. 全程通过 0x18FF1109 上报步骤状态，异常时上报错误码后停机或重试

## 2. CAN ID 分配

| CAN ID | 方向 | 用途 |
|---|---|---|
| 0x18DA03F1 | 工装 → 产品 | UDS 物理寻址请求 |
| 0x18DAF103 | 产品 → 工装 | UDS 物理寻址响应 |
| 0x18FF1108 | 产品 → 工装 | 产品心跳 (byte[0..3]=主版本4位, byte[4..7]=次版本4位) |
| 0x18FF1109 | 工装 → 产品(总线) | 工装步骤状态上报 |

| 参数 | 值 | 说明 |

| TOOL_FW_VER_MAJOR | 3 | 工装固件主版本号 |

| TOOL_HB_VER_MINOR_IDX | 4 | 心跳帧次版本起始字节 |

| TOOL_FW_STORE_ADDR | 0x0001A000 | 工装内部 Flash 镜像存储起始地址 |
| TOOL_FW_SIZE | 0x18000 (96KB) | 全量镜像大小 |

## 4. 状态机总览

```
LISTEN ──版本比对通过──> EXT_SESSION ──50 03──> UNLOCK_APP ──解锁成功──> JUMP_BOOT
   ^                                                                        │
   │                                                            71 正常响应──┼──> PROG_SESSION
   │                                                            超时(静默复位)─┼──> WAIT_BOOT ──71 01 FF 00──┘
   │                                                                          │
   └──DONE_DELAY(3s)──WAIT_5101<──ECU_RESET(11 01)<──EXIT(37)<──TRANSFER(36xN)<──DL_REQ(34)
                          │                                                        ^
                          │超时且心跳版本已达标的兜底                                │
                          └──> DONE_DELAY                                          UNLOCK_BOOT (10 02 之后)
```

| 状态 | UDS 服务 | 说明 |
|---|---|---|
| LISTEN | — | 监听心跳，3 帧防抖后比对版本，决定是否升级 |
| EXT_SESSION | 10 03 | 进扩展会话，期望 50 03 |
| UNLOCK_APP | 27 01/02 | APP 上下文安全解锁：取 seed → 发 key |
| JUMP_BOOT | 31 01 | 请求产品进 bootloader，产品静默复位无响应属正常 |
| WAIT_BOOT | — | 等 boot 补发 71 01 FF 00 (15s 超时) |
| PROG_SESSION | 10 02 | 进编程会话，期望 50 02 |
| UNLOCK_BOOT | 27 01/02 | boot 上下文重新解锁 (seed/key 与 APP 不同) |
| DL_REQ | 34 | 请求下载，携带 0x08018000 + 96KB |
| TRANSFER | 36 x N | 按块发送 256B 数据，逐块等 76 肯定响应 |
| EXIT | 37 | 退出传输，期望 77 |
| ECU_RESET | 11 01 | 请求复位，产品静默复位 |
| WAIT_5101 | — | 等 APP 重启后补发 51 01 (15s 超时) |
| DONE_DELAY | — | 3s 静默期后回 LISTEN，只认静默期后收到的心跳 |
| RETRY_DELAY | — | 整流程失败后延迟 2s 再回 LISTEN 重试 |
| ERROR | — | 错误停机 (重试耗尽)，需重新上电恢复 |

## 5. 心跳版本监听与防抖 (LISTEN)

1. 收到 0x18FF1108 后解析版本号：主版本 = byte[0..3] 按千/百/十/个位十进制，次版本 = byte[4..7]，折算为 主*10000+次 的数值 (0002.2000 -> 22000)
2. **连续 TOOL_HB_CONFIRM_CNT(3) 帧版本一致才判定可信**：与上一帧相同则计数+1，不同则计数重置为 1；不足 3 帧不做版本判断
3. 版本可信后：产品版本 < 工装版本 → 触发升级；否则继续监听
4. 每次进入 LISTEN (上电初始 / 升级成功静默期结束 / 重试返回) 都清零计数重新累计
5. 升级成功后的 3s 静默期 (DONE_DELAY) 用于丢弃复位在途/残留心跳，避免旧版本心跳误触发第二轮刷写
6. WAIT_5101 兜底：若等 51 01 超时但心跳显示版本已达标，同样视为升级成功

防抖设计目的：升级后新旧 APP 心跳交替、孤立异常帧不会误触发升级；但若新 APP **持续性**广播错误版本 (如 byte[0..3] 恒为 0)，达到确认帧数后仍会触发刷写。

## 6. 升级流程 UDS 时序

```
工装                                产品(APP)
 │ 10 03 扩展会话                     │
 │ ────────────────────────────>     │ → 50 03
 │ 27 01 取 seed                      │
 │ ────────────────────────────>     │ → 67 01 + seed
 │ 27 02 发 key (seed异或运算)         │
 │ ────────────────────────────>     │ → 67 02 解锁成功
 │ 31 01 进 boot 例程                  │
 │ ────────────────────────────>     │ → 产品静默复位 (无响应属正常)
 │                                    ↓
 │                          boot 补发 71 01 FF 00 (或等 15s 超时)
 │ 10 02 编程会话                      │
 │ ────────────────────────────>     │ → 50 02
 │ 27 01/02 (boot 上下文重新解锁)       │
 │ 34 请求下载 (0x08018000, 96KB)      │
 │ ────────────────────────────>     │ → 74
 │ 36 块1 数据(256B+seq) ──> 76        │  (逐块发送, P2 从最后一个 CF 发完开始计时)
 │ 36 块2 ...                          │  (seq 1..N, 0xFF 后回绕 1)
 │ 37 退出传输                          │
 │ ────────────────────────────>     │ → 77
 │ 11 01 复位                          │
 │ ────────────────────────────>     │ → 产品静默复位, 重启进新 APP
 │  <── 新 APP 心跳 0x18FF1108         │
 │ 51 01 补发 (或心跳版本兜底)           │
 │ 3s 静默 → 回 LISTEN 判版本           │
```

## 7. 超时与重试策略

| 场景 | 参数 | 值 |
|---|---|---|
| 单次 UDS 请求-响应 (P2) | TOOL_TIMEOUT_P2_MS | 5000ms (0x36 从最后一个 CF 发完才起算) |
| ISO-TP 流控帧等待 (N_Bs) | TOOL_TIMEOUT_FC_WAIT_MS | 10000ms |
| 31 01 后等 71 01 FF 00 | TOOL_TIMEOUT_BOOT_READY_MS | 15000ms |
| 11 01 后等 51 01 | TOOL_TIMEOUT_RESET_ACK_MS | 15000ms |
| NRC 0x22 延迟重试 | TOOL_NRC22_RETRY_DELAY_MS / MAX | 5000ms x 3 次 |
| 0x36 单块失败重发 | TOOL_BLOCK_RETRY_MAX | 3 次 |
| 整流程失败重试 | TOOL_FLOW_RETRY_MAX / DELAY | 2 次 (总尝试 3) / 2000ms |

## 8. 步骤状态上报 (0x18FF1109)

帧格式: byte[0]=步骤码, byte[1]=参数, byte[2]=细节，其余为 0。

| 步骤码 | 含义 |
|---|---|
| 0x00 IDLE | 空闲监听心跳 |
| 0x01 VERSION_OK | 版本比对通过，触发升级 (byte[1]=产品版本) |
| 0x02 EXT_SESSION | 10 03 扩展会话 |
| 0x03 UNLOCK | 27 安全解锁 |
| 0x04 JUMP_BOOT | 31 01 请求进 boot |
| 0x05 PROG_SESSION | 10 02 编程会话 |
| 0x06 DOWNLOAD | 34/36 下载中 (byte[1]=进度%) |
| 0x07 TRANSFER_EXIT | 37 退出传输 |
| 0x08 ECU_RESET | 11 01 复位等待 |
| 0x09 DONE | 升级完成 (byte[1]=100) |
| 0x0F ERROR | 错误停机 (byte[1]=错误码) |

上报带去重：相同 step/param/detail 不重复发送。

## 9. 错误码 (step=0x0F 时 byte[1])

| 错误码 | 名称 | 含义 |
|---|---|---|
| 0x01 | P2_TIMEOUT | UDS 响应超时 |
| 0x02 | NRC | 否定响应 (byte[2]=NRC 码) |
| 0x03 | ISOTP | ISO-TP 发送失败 |
| 0x04 | NRC22_EXHAUSTED | 0x22 重试耗尽 |
| 0x05 | SECURITY_DENIED | 0x33 解锁流程失败 |
| 0x06 | FLOW_RETRY_EXHAUST | 整流程重试耗尽 |
| 0x07 | BOOT_READY_TIMEOUT | 等 71 01 超时 |
| 0x08 | RESET_ACK_TIMEOUT | 等 51 01 超时 |

## 10. 关键设计决策与踩坑记录

- **肯定响应判定**：UDS 肯定响应 SID = 请求 SID + 0x40 (如 10→50、27→67)，`UdsTester_TxnResp()` 返回的是去掉 SID 后的负载
- **块大小必须 4 字节对齐**：曾因 258B 块导致 Flash 写地址 0x1A102 非字对齐，`EFM_ProgramWordReadBack` 挂死无 76 响应，P2 超时误报。改为 256B 后地址始终对齐
- **0x36 P2 计时起点**：多帧发送时从**最后一个 CF 发送完成**才开始计时，期间持续重启 P2，避免大数据块被误判超时
- **27 02 重试规则**：解锁重试必须复位子状态、从 27 01 重新取 seed；直接重发 27 02 会得到 NRC 0x24 (requestSequenceError)
- **31 01 响应处理**：收到 71 响应应直接进入 10 02 编程会话，无需再等额外报文；静默复位无响应则等超时后转 WAIT_BOOT 等 boot 补发
- **11 01 成功判定**：TXN_OK 即代表已收到 51 01 (uds_tester 内部已校验 SID+0x40)，立即判成功，禁止再进 WAIT_5101 重复等待
- **地址映射**：0x34 发的是虚拟映射地址 0x08018000，仅用于告知 bootloader 烧录到 APP1 区 (0x1A000)
- **NRC 0x22** (conditionsNotCorrect)：多为产品不在预期上下文，延迟 5s 后从当前步骤重试
- **日志约定**：TX/RX 报文说明直接附在 `<--` 后 (如 `<--36 cont`)；NRC 附带名称解释；`[TOOL]` 行带时间戳
